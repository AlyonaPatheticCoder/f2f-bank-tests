В ходе выполнения e2e-тестирования были обнаружены следующие дефекты и потенциально неожиданное поведение приложения.

# Bugs

## BUG-01 - Ошибка загрузки баланса при первом открытии приложения

**Severity:** Medium  
**Priority:** Medium

### Description

При первом открытии главной страницы приложения отображается сообщение:

```
Failed to load balance
```

### Preconditions

- Приложение запущено.
- Пользователь открывает приложение впервые или не авторизован.

### Steps to reproduce

- Открыть приложение по адресу `http://localhost`.
- Не выполнять вход в аккаунт.
- Дождаться полной загрузки страницы.

### Actual result

На странице отображается сообщение:

```-
Failed to load balance
```

### Expected result

Для неавторизованного пользователя запрос баланса не должен приводить к отображению ошибки.


## BUG-02 - Перевод можно выполнить на номер телефона незарегистрированного пользователя

**Severity:** Medium  
**Priority:** Medium

### Description

Приложение позволяет выполнить перевод на любой номер телефона, соответствующий формату валидации, даже если получатель с таким номером не зарегистрирован в системе.

### Preconditions

- Пользователь авторизован.
- На балансе пользователя достаточно средств.

### Steps to reproduce

- Авторизоваться в приложении.
- Открыть форму перевода.
- Ввести номер корректный телефона.
- Ввести положительную сумму.
- Ввести назначение платежа.
- Нажать `Send`.

### Actual result

Перевод успешно выполняется. Пользователь не проверяется на существование в системе.

### Expected result

Если приложение предназначено для переводов между зарегистрированными пользователями, перед выполнением операции необходимо проверить наличие получателя.

# Unexpected behavior

## NOTE-01 - Произвольные символы в телефоне удаляются перед валидацией

При обработке номера приложение удаляет нецифровые символы перед проверкой количества цифр.
Например:
```text
+7 (999) 123-45-67
```
преобразуется к последовательности цифр перед валидацией.

Это позволяет корректно обрабатывать варианты форматирования номера, но такое поведение одновременно приводит к BUG-003: строки с буквами также могут быть приняты.

## NOTE-02 - Пароль может содержать пробелы внутри

В тестах проверяется возможность использования пробела внутри пароля. Такое значение считается валидным с точки зрения HTML-валидации.

## NOTE-03 - Сервер предъявляет дополнительные требования к email

В тесте LOGIN-010 используется адрес:

test@example

и ожидается ошибка входа. При этом браузерная HTML-валидация может считать такой email допустимым с точки зрения базового формата поля type="email".
есть потенциальное различие между:

- клиентской валидацией HTML;
- требованиями серверной части к email.
